# Настройка

Следуйте корневому README. Compose запускает только PostgreSQL 16; приложения запускаются отдельно. База vpn_backend, пользователь и пароль postgres — исключительно локальные значения. При занятом порте задайте POSTGRES_PORT для Compose и тот же DATABASE_PORT в backend/.env. Команда docker compose stop db сохраняет данные volume. Не подключайте пример к рабочей базе: TypeORM synchronize может менять схему.

Frontend использует NEXT_PUBLIC_API_URL без /api в конце и NEXT_PUBLIC_SITE_URL. Они встраиваются при сборке; после изменения пересоберите frontend. CORS backend настраивается через FRONTEND_ORIGIN. При других портах согласуйте настройки обеих частей; backend читает PORT (по умолчанию 3200), Next принимает --port.

## Интеграции

- Telegram: создайте своего бота, задайте TELEGRAM_TOKEN, TELEGRAM_BOT_USERNAME, включите TELEGRAM_BOT_LAUNCH. Настройте свой канал и права бота. Для роли администратора укажите свои числовые Telegram ID в TELEGRAM_ADMIN_IDS; роль определяется при Telegram-авторизации/связывании аккаунта. Готового администратора и пароля нет.
- Контакты: замените примеры в backend/src/bot/bot-legal.ts, backend/src/bot/bot.constants.ts и frontend/src/shared/config/legal.ts; согласуйте URL и support-параметры .env. Legal-тесты содержат ожидаемые значения примеров.
- Remnawave: нужны отдельная панель и VPN-ноды. Задайте URL панели, API-токен, публичный URL подписок и при необходимости UUID squad. Панель и ноды сюда не входят.
- Платежи: нужны свои аккаунты провайдеров. Platega в примере указывает на payments.example.invalid; настройте действительный API URL и свои merchant credentials. Для YooKassa отдельно настраиваются SITE/BOT-магазины, webhook, чеки и флаги включения. Возврат пользователя на сайт не подтверждает оплату: нужна серверная проверка статуса. Recurrent и reconciliation включайте после настройки и проверки провайдера.
- Поддержка: выделите отдельные Telegram-чаты для обращений и технических логов. В production обязательны разные TELEGRAM_SUPPORT_CHAT_ID и TELEGRAM_LOGS_CHAT_ID, а также существующая абсолютная директория SUPPORT_MEDIA_STORAGE_ROOT с правами чтения/записи вне src, dist, public. Вложения должны оставаться приватными.

Полный список настроек — backend/.env.example; обязательные условия проверяет backend/src/env.validation.ts. Для production замените JWT-секреты и все демонстрационные значения, настройте HTTPS, cookie domain/secure, постоянные volume и резервное копирование. Пример не является production-конфигурацией.

Юридические страницы сохраняют структуру прежнего продукта. Перед своим запуском замените сведения об операторе, контакты, условия и даты под собственный сервис.

## Docker и деплой

В каждой части сохранён Dockerfile как пример; контекст сборки — соответствующая папка. Корневой Compose запускается только вручную и поднимает базу для локального изучения. Репозиторий ничего не развёртывает и не подключён к Dokploy. GitHub Actions отключены, workflows и настройки CI/CD отсутствуют.
